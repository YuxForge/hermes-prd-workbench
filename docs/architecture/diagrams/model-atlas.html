01

DATA-MODEL

数据模型 · 八张表与两类关联

ER / DATA MODEL · 8 entities · 6 foreign keys + 2 logical links · V001—V013

关系按 V001–V013 的最终 DDL 表达。用户到任务的基数为 0..1 → 0..*，因为 prd_task.user_id 允许 NULL；其他任务子记录必须属于一个任务。运行到结果为 1 → 0..1，唯一约束 uk_agent_result_run 限制一次运行最多一条结果。

agent_run.parent_run_id 自关联可空，删除父运行时 SET NULL；其余外键删除策略为 CASCADE，准确清单见下表。prd_telemetry_event.user_id、prd_update_log.created_by 仅为逻辑关联，后者也可能是 system。

草稿与反馈没有新增表：当前稿为 prd_source 中按 SourceRoles 命名识别的记录，修改 content 时以 updated_at 做并发检查；原始 agent_result.payload 不随草稿修改。评审回复写入 agent_run.review_feedback，用 revision 做并发检查。图中 field grouping 与省略字段不构成新列。

02

UML-CORE

类图 · 任务与运行编排

UML CLASS · 6 classes · 7 dependencies · + public / − private

虚线箭头表示调用或使用依赖。Spring 注入的服务不画成生命周期组合。RunService 在单进程线程池执行任务，通过唯一的 Hermes HTTP 客户端发起与查询运行；启动时将遗留 RUNNING 标记 FAILED，用户手动重新运行。

TaskMutationGate 采用本进程 ConcurrentHashMap 与 ReentrantLock，按 taskId 互斥。ResultValidator 检查 mode、大小与最小结果结构。此视图省略 mapper、DTO、导出器和遥测依赖，分别在后续视图与清单说明；方法中的 ... 表示参数缩写。

03

UML-TOOLS

类图 · Agent 工具与评审反馈

UML CLASS · 6 classes · 7 dependencies · current-run scope

InternalToolController 在 /internal/v1/runs/{runId} 提供读取材料、写入工作区和提交结果的入口。ToolService 只向运行中的任务提供可见材料，并可添加历史评审决策作为虚拟上下文；虚拟上下文不是一张数据库表。

ReviewFeedbackService.update() 检查所有权、运行状态和反馈项，并通过 RunMapper.updateReviewFeedback() 比较 expectedRevision。RunService.acceptResult() 在事务内写结果与运行状态。为控制密度，此视图省略 ToolService→SourceMapper、反馈服务→TaskService/TaskMutationGate、RunService→ResultMapper 等依赖；完整关键依赖清单列于页尾。

UML-PERSISTENCE

类图 · MyBatis-Plus 持久化接口

UML CLASS · 5 interfaces · 4 generalizations · generic binding

空心三角 + 实线表示接口继承。Java 接口使用 extends BaseMapper<Entity>，不画成 implements 实现关系。绑定分别是 TaskMapper→TaskEntity、SourceMapper→SourceEntity、RunMapper→RunEntity、ResultMapper→ResultEntity。BaseMapper 为框架接口，非仓库自定义类。

CRUD 由 BaseMapper 继承，图中仅列仓库新增操作。SourceMapper.updateDraftContent() 以 expectedUpdatedAt 比较更新；RunMapper.updateReviewFeedback() 以 revision 比较更新。其他四个 Mapper 同样继承 BaseMapper，映射见下表。

UML-AUTH

类图 · 本地账号与会话认证

UML CLASS · 6 classes / interfaces · 5 dependencies

AuthService 通过 UserMapper / SessionMapper 管理本地账号与会话。原始令牌由客户端持有，数据库保存 token_hash；密码以 password_hash 保存，图中只展示字段名。

SessionAuthInterceptor 调用认证服务并设置/清理 CurrentUser 线程上下文；AuthController 的 me()、logout() 也使用 CurrentUser，此跨图依赖未连线。管理员校验、启动管理员初始化、凭证算法与 DTO 留在源码中。

06

UML-ADMIN

类图 · 遥测与更新日志

UML CLASS · 6 classes / interfaces · 5 dependencies

TelemetryService 汇总事件、用户/任务/运行统计及失败信息，浏览器遥测默认关闭。AdminUpdateLogController 在修改日志时调用 TelemetryService 记录事件；UpdateLogMapper 和 TelemetryEventMapper 也继承 BaseMapper<对应实体>。

为满足每个分区最多 7 类的阅读预算，此处省略普通遥测/更新日志查询控制器、用户管理控制器和 ObjectMapper 等通用依赖；SummaryResponse 是 UpdateLogModels.UpdateLogSummaryResponse 的显示缩写。

七种运行模式与四种运行状态

REVIEW · GENERATE · DEMO · POC · ESTIMATE · TEST_CASE · TECH_SPEC

PENDING · RUNNING · SUCCEEDED · FAILED。数据库 mode/check 约束以 V012 为最终态；RunService 与 contracts/openapi.yaml 保持同一模式清单。accepted 是用户确认标记，不是第五种运行状态。

JSON 内部对象与持久化边界

Review、PRD、Demo、POC、Estimate、TestCase、TechSpec 的业务输出按各自 contracts/*.schema.json 存入 agent_result.payload，文件包可内嵌在 payload 中；没有为每种输出单独建表。review_feedback 单独保留在 agent_run。工作区临时文件和源文件由本地存储承载，不扩展成关系实体。
