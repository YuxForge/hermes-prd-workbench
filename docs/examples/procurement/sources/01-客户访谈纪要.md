# 设备采购与审批：客户访谈纪要

> 完全虚构的公开演示材料。组织、人物、单据与金额均为合成数据，不对应任何客户。

## 场景与目标

虚构组织「青岚工坊」有三个部门：设计部、研发部、运营部。办公设备采购目前依赖聊天和表格：申请人发需求，主管回复同意，采购员自行下单，仓管再核对到货。月底常常不知道某笔采购是否已经审批、是否收齐。

一期做一个桌面端设备采购工作台，覆盖四个模块：采购申请、审批待办、采购订单、收货登记。管理层希望能从申请一路查到审批、订单与累计收货，不做资产折旧或财务付款。

## 角色与流程

- 申请人只看自己的申请，可保存草稿、编辑草稿、提交，查看驳回理由。
- 部门主管只能审核本部门申请，不能审核自己的申请。
- 采购员只能对已批准申请建采购订单，并录入供应商、预计到货日和明细。
- 仓管只登记已下单订单的实际收货数量，可分多次收货，全部收齐后订单完成。
- 系统管理员维护角色；本期演示预置人员，不做企业通讯录或组织系统集成。

申请至少有标题、所属部门、用途、期望到货日、物品明细。每行物品包含名称、规格、数量、单价。总额按行汇总，只使用人民币，保留两位小数。

主管在会上说：“金额不超过 5,000 元的申请，我同意就能买；超过 5,000 元还要财务复核。”财务复核角色的归属和自审替代人还没有确定。

## 必须支持的异常

- 驳回必须写明原因；申请人希望能修改后重新提交，但没有讨论是否沿用单号。
- 多人同时点审批时不能出现一张单既批准又驳回。
- 数量必须大于零，单价不能为负。提交后不能直接编辑正在审批的明细。
- 收货量不能大于待收数量；累计收货量与订单状态应一致。

- 扩展坞：2 个，单价 450.00 元。
- 合计：4,500.00 元。
