# 当前 PRD 人工校对记录

> 维护者在真实模型 PRD 生成后，经独立审查人工编写。用于公开说明模型草案需要人工复核；不是 Agent 自动修复，也没有改写数据库中的原始 Agent 结果。

## 校对决定

1. 权限表「修改已驳回单」误将低额本人权限放在采购员列。删除此权限；采购员和仓管不新建、不编辑、不提交采购申请。
2. 财务本人低额申请缺主管，原文 Q1 与权限表不一致。当前演示沿用 Q1 的保守临时处理：方宁可保存草稿，所有本人申请均不可提交，直到明确部门和非本人审批人。高额申请保留缺财务复核员提示，低额申请提示缺本部门主管。该限制必须显式展示，不能宣称已解决真实组织授权。
3. 草稿可暂存缺失的必填项，但已填写的格式必须合法；提交审批才做完整必填校验。将 AC01 的「标题、用途为空」校验动作改为提交审批；过去日期与非法数量/单价仍禁止保存。
4. 收货列表统一按创建时间倒序，保持 D07 口径，不采用模型自行增加的预计到货日升序。
5. 财务数据范围限跨部门待财务复核申请，删除信息架构中额外授予的订单、收货记录查看权限。
6. 本部门历史只读权限的待确认引用由 Q5 校正为 Q3。Q3 仍是临时假设，并未替代真实业务方授权。
7. 申请编号冲突返回错误并由用户手动重试，不引入自动重试或分布式编号基础设施。
8. 对独立当前稿去除重复叙述，整理为[人工校对 V3 运行基线](06-人工整理的运行基线.md)，不替换原始模型包。进一步明确：未参与收货行可空或0、不生成明细；本次至少一行大于0，实际收货行须为不超过待收量的正整数；整单全0必须拦截。

## 版本边界

上述校对通过工作台编辑功能保存到独立当前稿。原始 12 文件 PRD 包仍是生成时快照，下载包中保留其原样，不能把它误当成已全部校对的实现规格。公开案例单独提供 `current-prd.md` 作为人工校对后的当前稿。

原型若在校对前生成，应人工检查并显式手动重跑，后续测试用例、技术方案、估算均以校对后当前稿为准。六条模型待确认问题继续保留，不能宣称生成后即可直接上线。实际点击覆盖范围见案例验证记录。
