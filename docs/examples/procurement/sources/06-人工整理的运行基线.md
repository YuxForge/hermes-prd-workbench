# 设备采购与审批：人工校对 V3 运行基线

> 本稿由维护者在真实 12 文件模型 PRD 及独立审查基础上人工整理，去除重复叙述并修正《05-人工校对记录》列出的问题。它通过工作台编辑功能保存为独立当前稿；原始 Agent PRD 包不变。组织、人员、单据均虚构。本稿服务于合成案例演示，真实实施仍需业务方确认假设和技术设计。

## 目标、范围与四个模块

虚构组织青岚工坊希望把聊天与表格采购流程串起来：采购申请 → 审批待办 → 采购订单 → 收货登记。覆盖申请、两级审批、下单、按行分批收货及只读时间线，并产出案例交付资料。只使用人民币；不做付款、税额拆分、库存、资产折旧、退货、撤销收货、撤回审批、取消订单、供应商接口、邮件短信或企业通讯录集成。预置角色，不增加角色管理模块。

原型为纯内存静态单文件 HTML：四个一级导航、中文列表/详情/表单、合成数据、角色切换；全部 CSS/JS 内联，不联网、不访问存储，刷新恢复种子数据。角色切换仅演示界面规则，不能证明正式系统的认证、权限或并发安全。正式系统另需 Java 21/Spring MVC、MySQL 8.4、Vue 3 的实现和验收，不引入消息队列、分布式锁或独立幂等基础设施。

## 统一数据规则

| 对象/字段 | 规则 |
| --- | --- |
| 申请标题 | 提交时必填，1–100 字 |
| 用途 | 提交时必填，1–500 字 |
| 部门 | 由预置人员归属取得，不允许申请人任意改部门 |
| 期望到货日 | 提交必填；已填写时不得早于当天；历史记录保留原值 |
| 物品明细 | 提交至少一行；名称1–100字、规格最多100字、单位台/个/件 |
| 数量与单价 | 数量为1–999整数；单价0–999999.99元、最多两位小数；0元合法 |
| 金额 | 以分计算行金额并汇总，显示两位小数；不得使用浮点误差改变审批路由 |
| 单号/版本 | 首次保存生成唯一申请号；原单重提不换号；版本和审批轮次递增 |
| 供应商 | 下单必填，自由文本1–100字，无独立供应商主数据模块 |
| 预计到货日 | 下单必填，不早于下单日 |
| 驳回理由 | 必填，1–200字；时间线只读保留 |
| 收货数量 | 实际收货行是正整数且不超过该行待收量；未参与行可空或0，不生成明细；至少一行大于0 |

草稿允许缺失必填项暂存，但已填的日期、数量、金额等格式必须合法。**提交审批才执行全量必填校验。**新建/提交不能生成重复单号。正式系统若编号或状态冲突，返回409并由用户手动重试，不自动重试。所有列表按创建时间倒序、10条/页，支持单号/标题搜索、状态筛选和「暂无匹配单据」空状态。

## 角色与数据边界

| 角色/虚构人员 | 申请与审批 | 订单与收货 |
| --- | --- | --- |
| 申请人林沐/设计部、陈星/研发部 | 仅自己的申请，可建草稿、编辑草稿/驳回单、提交、看历史；不能审批 | 只读本人申请关联的订单和收货进度，不能建单/下单/收货 |
| 设计主管周禾、研发主管许原 | 可发起本人申请；只能审本部门待审批单及明确授权的代审单，不得审本人 | 可只读本部门申请关联进度，无采购/收货动作 |
| 财务复核员方宁 | 跨部门待财务复核单，可通过/驳回，但不能审本人。本人申请可存草稿，所有金额均不可提交 | 不可查看订单或收货记录，不可代采购/仓管执行动作 |
| 采购员苏青 | 只读履职需要的已批准申请，不可新建、修改或提交申请，不审批 | 可建单/下单、查看订单和收货记录，不登记收货 |
| 仓管白舟 | 仅查看已建单申请的必要关联信息，不可新建、修改、提交或审批 | 查看待收货/部分收货订单及历史记录，可登记收货，不建单/下单 |

周禾自己的申请由许原代审，许原自己的申请由周禾代审；这只授权对方本人的申请，不授予普通跨部门审批权。代审须留痕。方宁高额申请提示「缺少非本人财务复核员，请联系管理员安排人员」，低额申请提示「缺少本部门主管，请联系管理员安排人员」；均保留草稿，不产生待办。此为案例对原Q1的保守临时决定。

主管全量历史查询不另开入口（原Q3仍需真实业务确认）；前述本部门进度只读展示也必须经过业务授权后实施。正式服务端必须按角色和数据范围拒绝越权，前端隐藏按钮不能替代403；冲突返回409并提示刷新。

## 模块一：采购申请

申请列表展示申请号、标题、申请人、部门、总额、状态、创建时间与详情操作。新建表单按统一字段表校验；保存合法草稿生成号、版本1、轮次1；提交成功后进入待主管审批，申请人不能再编辑或撤回。已批准申请永久只读，特别是已建单后不能改动订单来源。

申请状态：草稿 → 待主管审批 → 已批准，或草稿 → 待主管审批 → 待财务复核 → 已批准。任何审批层驳回都到已驳回。原申请人可修改已驳回单；再次提交沿用单号，版本/轮次各加1，从主管重新开始。旧轮审批记录只读，不沿用上一轮通过结果。草稿、待审批、已驳回不可被采购建单。

详情关联显示申请字段、行明细、全部审批轮次、只读操作时间线，以及订单号与累计收货进度。原型必须显示「刷新恢复合成种子数据」；正式系统刷新则应保留已保存数据。

## 模块二：审批待办

主管与财务待办在同一个模块按当前角色显示。主管审批金额 **≤5,000.00元** 的申请通过后直接已批准；**>5,000.00元** 进入待财务复核，只有财务再通过才已批准。财务驳回也到已驳回。5,000.00元走单级，5,000.01元与8,600.00元走两级，不使用10,000元口径。

审核详情展示申请、用途、金额、轮次和历史；通过/驳回均显式确认，驳回缺理由时停留原状态并报错。本人审批拦截。正式系统使用事务内状态和版本条件更新，只有一方成功，重复或竞争动作返回409；静态原型只验证单浏览器状态，不宣称并发正确。

## 模块三：采购订单

采购员在已批准申请上创建订单，一个申请最多一个订单。物品、数量、单价来自批准版本的只读快照，采购员不可改；重复建单必须显示已有订单或冲突，不产生第二张。建单后状态待下单；填供应商与预计到货日，校验通过后下单进入待收货。未下单不可收货。不提供编辑已下单订单、取消、付款动作。

订单列表展示订单号、关联申请、供应商、金额、状态、创建时间、收货进度。详情展示明细快照与只读时间线。申请本身保持已批准；订单进度关联展示，不另造申请「已完成」状态。

## 模块四：收货登记

仓管只对待收货或部分收货订单登记本次到货量。每行显示订购数、累计已收、待收和本次数；未参与行可空或0，不生成收货明细；本次提交至少一行大于0，实际收货行必须为正整数且不超过待收量。全0、负数、小数或超收无效，不写记录、不改累计。合法收货新增只读记录，记录号、登记人、时间、各行本次数与备注可在详情核对。

任一行未收齐且已有收货为部分收货；全部行累计数量等于订购量才已完成；待下单和已完成无收货入口。可两次或多次分批收货。正式系统在同一事务中校验剩余量、写收货记录和推进状态，竞争超收返回409；历史记录不可改，不提供退货或撤销。

## 验收清单

| 编号 | 可核对的通过条件 |
| --- | --- |
| AC01 | 缺标题/用途允许合法草稿暂存，提交必填拦截；非法日期/数量/单价格式不保存 |
| AC02 | 5,000.00元单主管通过即批准，不出现财务待办 |
| AC03 | 5,000.01元和8,600.00元主管通过后仍不可建单，财务通过后才允许 |
| AC04 | 自审拦截；周禾/许原仅对明确授权的对方本人申请代审并留痕；方宁本人不可提交 |
| AC05 | 驳回必须说明；原单重提号不变、轮次/版本增加，完整重走审批，旧记录只读 |
| AC06 | 未批准不建单；一个批准申请仅一个订单；供应商/预计日期缺失不能下单 |
| AC07 | 分批收货允许部分行空或0，只增加实际收货行的合法数量；超收/全0提交拦截；全部行收齐才完成 |
| AC08 | 采购仓管不编辑申请、财务不读订单/收货；按数据范围只读历史，正式系统服务端403/409需独立测试 |
| AC09 | 静态原型刷新还原种子数据；正式系统刷新保持持久数据；两者不混为一个验收结论 |

演示种子包含显示器2台×1,800元、扩展坞2个×450元（共4,500元）和工作站1台×8,600元；金额与状态应可在现场核对。未真实点击的路径不能宣称已验收。

## 人工仍须确认的假设与估算范围

原模型的Q1–Q6保留于原始包：财务本人低额申请、编号格式、主管历史范围、到货日期上限、重提审批人、长期未收齐处置。本合成基线临时选择：方宁本人仅草稿；单号只要求唯一、可采用SQ/DD/SH前缀；不新增历史入口；未来日期不设上限；重提按角色池先到先审但仍不得自审；部分收货不提醒、不自动关闭。真实业务方需逐项确认，不能把案例默认当成公司制度。

后续测试用例引用AC编号，区分原型点击与正式系统权限/并发测试。技术方案描述四模块表、关系、约束、API和事务，不能把待开发设计说成已上线功能。工作量只估开发与研发自测，不含产品设计、项目管理、运维部署和第三方费用，不使用固定公司费率，不承诺确定工期。
