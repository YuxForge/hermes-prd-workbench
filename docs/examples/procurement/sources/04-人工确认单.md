# 设备采购与审批：人工确认单

> 合成案例维护者根据真实 Agent 评审人工编写，代表虚构业务方作出演示决策；不是模型自行统一口径，不是真实客户批准。用于替代 01、02 中未决或相互冲突的规则，其他范围不变。

## D01：审批额度

按申请明细合计的人民币金额判断，单价最多两位小数，数量为 1–999 的整数，单价范围 0–999999.99 元。逐行计算后汇总，禁止使用浮点误差改变路由。金额 ≤5,000.00 元，主管通过后批准；金额 >5,000.00 元，主管通过后进入待财务复核，财务通过后才批准。5,000.00 元无需财务；5,000.01 元和 8,600.00 元需要财务。本期固定阈值，不做配置中心或税额拆分。

## D02：审批入口与状态

财务复核放在「审批待办」模块内，以角色筛选待办。申请状态为草稿、待主管审批、待财务复核、已批准、已驳回。两级审批驳回均到已驳回。财务可看跨部门待财务复核单；任何审批都不能由申请人自己执行。

## D03：自审与数据范围

设计部主管周禾的申请由研发部主管许原代审；研发部主管许原的申请由设计部主管周禾代审，代审操作写入审计记录。此为固定演示授权，不赋予普通主管跨部门审批权。财务复核员方宁的高额申请一期禁止提交，提示「缺少非本人财务复核员，请联系管理员安排人员」，避免无审批人死单。申请人只看自己单据；主管看本部门待办及明确授权代审单；采购员、仓管可跨部门查看履职需要的已批准单、订单与收货明细，不可互代执行采购和收货。预置角色不开放管理界面，不做第五个角色维护模块。

## D04：驳回重提

驳回后申请人修改原单并重新提交，单号不变，版本与审批轮次递增；上一轮记录只读，新一轮重新走完整审批链。正在审批时不允许修改或撤回。采购订单只能对应已批准版本，已建单申请不能再编辑。历史申请数据不迁移。

## D05：订单与收货状态

一个申请最多一个订单。订单为待下单、待收货、部分收货、已完成；建单进入待下单，录入供应商和预计到货日后下单进入待收货，累计部分到货进入部分收货，全部行收齐才完成。申请详情关联显示订单和按数量汇总的收货进度，申请本身保留已批准状态。无取消、退货、收货撤销、订单修改功能。

## D06：重复操作与原型边界

正式系统用事务内的状态/版本条件更新防重复审批，用申请关联唯一约束防重复建单，收货写入时再次校验待收量，冲突返回 409 并提示刷新。本期不引入消息队列、分布式锁或独立幂等基础设施。静态原型只演示单浏览器交互，不宣称证明并发安全；数据仅保存在内存，刷新明确回到合成种子数据。

## D07：字段与列表

保存草稿时生成唯一申请单号；订单、收货记录分别有独立编号。标题 1–100 字，用途 1–500 字，物品名称 1–100 字，规格最多 100 字，单位从台/个/件中选择。驳回理由必填，1–200 字。期望到货日不能早于当天。供应商为必填自由文本，1–100 字；预计到货日不能早于下单日。收货数量为正整数且不超过对应行剩余量。

各列表支持单号/标题搜索与状态筛选，按创建时间倒序，10 条一页；无结果时显示「暂无匹配单据」。审计时间线展示操作人、时间、动作、备注与审批轮次，只读，按单据权限可见；一期不做审计导出、自动清理或归档。

## D08：交付与验收

验收编号至少覆盖 AC01 草稿与必填校验、AC02 5,000.00 元主管单级审批、AC03 5,000.01 元及 8,600.00 元财务二级审批、AC04 自审与代审、AC05 驳回原单重提、AC06 一申请一订单、AC07 分批收货与超收拦截、AC08 数据范围与只读历史、AC09 静态原型刷新重置。PRD、测试和技术方案应引用这些编号。工作量仅含开发与研发自测；模型结果是待人工核对的辅助草案。
