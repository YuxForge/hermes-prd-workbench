# 设备采购与审批：现状与交付约束

> 本文与其余输入均为人工编写的合成案例，供公开复现。

## 现有资料

旧表格只有申请标题、申请人、部门、设备名、数量、预估单价、主管留言和采购备注。没有固定单号，没有结构化审批记录，也没有分批收货记录。

公开案例使用以下虚构用户：设计部申请人「林沐」、研发部申请人「陈星」、设计部主管「周禾」、研发部主管「许原」、采购员「苏青」、仓管「白舟」、财务复核员「方宁」。演示不得使用真实姓名、电话、公司地址、邮箱或真实订单。

## 期望交付

1. 可供讨论的 PRD 文档包：流程、状态、权限矩阵、字段校验、异常、验收标准，以及明确的待确认事项。
2. 需求评审报告：重点找出影响实现的冲突与空白，保留材料依据；没有依据时写清假设。
3. 一个可点击的静态演示原型：采购申请、审批待办、采购订单、收货登记四个一级入口，使用内存中的虚构数据。
4. 测试用例：覆盖正常链路、金额边界、异常、角色权限和重复操作，不能把静态演示当成并发安全的证明。
5. 技术方案：描述真实业务系统应如何实现四个模块、数据关系与接口，以及静态原型和正式系统的区别。
6. 工作量估算：明确仅估算开发与研发自测，不含产品设计、部署运维、项目管理和第三方服务费用。

## 输出约束

所有结果为模型辅助草案，发布前由人核对。不能宣称可以直接生产部署或替代采购合规审查。原型不连接后端、不调用外部网络、不包含账号密钥、不执行真实交易；全部 CSS 和 JavaScript 内联。

未经人工确认的审批阈值、自审替代人与驳回重提规则应显式标为待定，不能悄悄选一个口径当事实。评审后由用户记录最终决定，再用于后续交付物。
