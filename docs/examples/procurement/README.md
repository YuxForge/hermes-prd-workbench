# 从冲突需求到可讨论的交付包：设备采购与审批

这个公开案例围绕一个具体问题：客户给了会议纪要和补充规则，但审批额度相互冲突，研发该按哪一版实现？

四个业务模块贯穿整个案例：**采购申请 → 审批待办 → 采购订单 → 收货登记**。组织、人物、设备、单据和金额全部虚构。输入材料由维护者编写，成果通过本地一键启动的真实 Hermes 工作台生成，未用预制响应替代模型运行。

## 先看一个有业务含义的冲突

访谈纪要写的是「不超过 5,000 元，主管批准即可」；补充规则写的是「小于 10,000 元，主管批准即可」。4,500 元申请在两套规则下表现相同，**8,600 元的设计工作站却会走不同审批路径**。

真实评审指出了这一差异，还发现财务复核没有对应状态和入口、主管不能自审却没有替代人、驳回重提缺少单号与审批轮次规则等问题。维护者随后用[人工确认单](sources/04-人工确认单.md)代表虚构业务方明确决定，模型再据此生成后续草案。

人工决定采用 5,000.00 元边界：5,000.00 元无需财务复核，5,000.01 元和 8,600.00 元需要；财务复核位于审批待办内；驳回后原单修改重提并增加审批轮次。其他决定包括授权代审、订单唯一约束、分批收货和静态原型刷新重置。

ZIP 来自工作台「导出交付大礼包」功能；案例页上的说明由维护者编写。Agent 原始结果保持不变，人工补充只保存到当前稿和评审处理记录中。**ZIP 中的合并 PRD 和 12 文件 PRD 包均为 Agent 原始生成快照，不是编辑后的当前稿。**人工校对后的基线单独提供为 [current-prd.md](current-prd.md)，后续成果以运行时读取的当前稿为依据。

导出清单的「已交付」指文件已生成，不表示业务设计或实现已验收；包内沿用的「可开工」「可呈报」等模板措辞也不能替代人工评审。模型没有提供估算汇总人天，XLSX 明确显示「未提供」，保留 12 条开发/自测明细供核算，不将缺失合计当成零。

独立审查实际发现了权限矩阵错位、财务本人提交口径不一致、草稿暂存与必填验收矛盾、收货排序偏离确认单、财务额外读取订单/收货记录等草案问题。维护者通过工作台编辑当前稿人工修正，详细改动见[人工校对记录](sources/05-人工校对记录.md)。原始包保留这些问题供对照，不能直接作为实施规格；六条业务待确认问题仍保留。

## 输入材料与复现

1. [客户访谈纪要](sources/01-客户访谈纪要.md)：流程、角色、设备与第一套审批规则。
2. [业务规则补充](sources/02-业务规则补充.md)：第二套审批规则与未决问题。
3. [现状与交付约束](sources/03-现状与交付约束.md)：旧表格现状、交付范围与演示边界。
4. [人工确认单](sources/04-人工确认单.md)：评审后由维护者人工决定，作为后续输入。
5. [人工校对记录](sources/05-人工校对记录.md)：PRD 生成后独立审查发现的问题与人工修改范围。
6. [人工整理的运行基线](sources/06-人工整理的运行基线.md)：去重后的四模块当前稿，明确模型草案与人工判断的边界。

按仓库[快速开始](../../../README.zh-CN.md#快速开始)运行 `setup → start → doctor`，使用自己的工具调用模型配置。新建需求，上传前三份材料并评审；查看问题后记录处理决定，添加第四份材料，再生成 PRD。参照第五、六份材料人工校对并保存当前稿，依次生成 Demo、测试用例、技术方案和估算，最后导出交付大礼包。模型、配置与随机性会影响结果，复现不保证逐字相同。

## 使用与可信边界

这是可下载、可审查的合成案例，不是生产采购系统或客户成功证明。静态原型不连接正式后端，角色切换不能证明服务端权限或真实并发安全；刷新行为以界面及验证记录为准。技术方案和测试用例仍需人工评审。视频实际点击覆盖范围、发现的问题和未执行项见[验证记录](validation.md)。

生成 HTML 在线预览继续使用 `sandbox="allow-scripts"`，不授予 `allow-same-origin`；下载的原始 HTML 与隔离预览分开。公开包不包含账号密码、模型配置、运行日志或完整提示词。所有发布资产沿用仓库许可证，第三方权利说明见 [NOTICE](../../../NOTICE)。
